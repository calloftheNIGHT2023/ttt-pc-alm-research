# 402｜组合基线运行时加载边界修正

2026-09-25。397 原始预测、审计、查询风险和图文均保留，不覆盖、不重写。发现的是计时边界不一致，不是查询泄漏，也不是推翻所有单优化器比较。

## 已有证据

397 中两组合的所有 .25/.5 秒调用均只及时交付先验备用。检查源码发现：`deadline_prediction_worker_v1.prepare` 在无支持信息的 setup 阶段加载 `n24_optimizer_controls_v1`，而 `prefix_deadline_worker_v1.prepare` 的 portfolio 分支只加载 regression；优化器／读出运行模块直到 `fit_portfolio` 开始才导入。两者均声称分开记录无任务初始化，因此这一边界不一致必须修正。

对应宽预算原始实例 `preflight_v1/calls/5920002_n4_adam_gn64_anytime_b20000`：setup 为 0.6945901 秒；先验备用在 0.0263549 秒收到，第一阶段组合预测在 1.8681828 秒收到，最终包在 1.9097524 秒收到。该记录与源码支持延迟加载问题；不能仅凭它将所有延时都数值归因于导入，下面的新旧冷／暖复测会分开验证。

因此 397 组合行只能作为该版本的实际端到端结果，**不能用来声称超过已公平预热的强组合**。其他强单优化器仍保留：主预算下原主 active1024 为 .02187023731738，GN64 union 为 .02051744988340；预列 active512 为 .01878577846485。active512 是开发候选，不追溯替换原主，也不提供四旧任务的显著性声明。

## 新版本的唯一修正

新 worker 在发送 ready 之前、尚未收到任何支持时加载组合会使用的同一优化器与读出模块。仍记录 setup 耗时和进程内存，**不免费运行支持更新，不预计算几何，不缓存任务状态**。原 portfolio 算术、起点、步骤、先验、逐阶段读出、随机种子与消息顺序全部不变。旧版本源由 397 哈希冻结，不能编辑。
